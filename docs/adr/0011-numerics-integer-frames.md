# 0011 数值与时间：64 位浮点 + 精确运算，整数帧

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q40

## 背景

帧同步要求不同浏览器、不同机器上的模拟逐位一致。浮点的不精确函数在不同引擎上可能有差异。时间如果用浮点秒倒计时，会出现取整误差：Stronghold 里 1.0 秒的攻击间隔实测要 31 帧才结束，1.2 秒则是正常的 36 帧。

## 决定

- 用 64 位浮点，只用精确运算（加减乘除、开方等 IEEE 754 要求精确的运算）。
- 需要确定性的数学函数走 `@aue/math`，沿用 detmath 的做法，例如 `hypot`。
- ESLint 禁止 `Math.random`、`**`，以及不精确的 `Math` 函数。
- 时间一律用整数帧，30 帧/秒。秒换算成帧，按官方的取整规则。[PRTS](https://prts.wiki/w/促融共竞) 写的帧对齐规则是四舍五入；Stronghold 现在是向上取整，登记为已知差异。
- 伤害、生命、技力的每一处取整，都在规范里写明依据（见 [0040](0040-spec-traceability.md)）。

## 理由

- 精确运算在各引擎上结果一致，是跨浏览器逐位一致的前提。
- 整数帧没有倒计时误差。

## 后果

- 不能随手用 `Math.sin` 等函数，要自己实现并验证。
- 与 Stronghold 的取整差异要登记（见 [0043](0043-ci-gates-and-registry.md)）。
- 仍有浮点风险，靠跨引擎一致性检查进 CI、每晚大批量运行来防（见 [0042](0042-verification-suite.md)）。

## 备选方案

- 定点数 / 全整数模拟：计划未采用。
