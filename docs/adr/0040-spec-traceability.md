# 0040 书面规范与条款追溯

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q51

## 背景

模拟规则的每个细节（公式、取整、边界）如果只存在于代码里，就无法审查，也无法判断测试有没有覆盖到。

## 决定

- 书面规范放在 `docs/spec/<模块>.md`。
- 每一条有编号（比如"伤害-3：物理伤害下限"），写明公式、定义域、取整规则、边界情况。
- 每一条写明出处：数据表字段，或 [PRTS](https://prts.wiki) 的固定版本链接（带 oldid）。
- 测试名里写上它验证的条款编号。
- CI 检查两件事：每一条至少有一个测试；测试引用的编号都存在。检查由 `aue-check spec`（`@aue/testkit`）完成。

## 理由

规范加追溯，让"规则是什么、依据是什么、有没有测"都能被机器检查。

## 后果

- 写代码前要先写规范，有额外成本。
- PRTS 页面会变，所以引用必须带固定版本。
- 规范与已知差异登记表配合使用（见 [0043](0043-ci-gates-and-registry.md)）。
