# 0042 验证手段：穷举、随机、不变量、变换、覆盖率、整场随机

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q41, Q50

## 背景

单一种类的测试覆盖不了数值和状态机的边界。我们要的是数学上的严谨。

## 决定

六项全部采用：

1. 书面规范（见 [0040](0040-spec-traceability.md)）；
2. 追溯检查；
3. 差分测试（见 [0041](0041-stronghold-differential-testing.md)）：
   - 有限的小定义域全部穷举：4 个方向、攻击范围表里的所有形状、地块偏移；
   - 连续输入用固定种子生成大批随机样本，并专门覆盖 0、−0、极小值、极大值、取整边界；
4. 不变量测试（fast-check，固定种子，自动缩小反例）：比如物理伤害不低于攻击力的 5%；生命始终在 0 和上限之间；目标排序是稳定的全序；同一种子得到同样的结果；
5. 变换测试：比如把地图旋转 90°，结果应该相应旋转；
6. 覆盖率：纯机制模块的分支覆盖率不低于 95%，用 Node 自带的统计（`--experimental-test-coverage --test-coverage-branches=95`）。

另有整场战斗的随机测试：用随机阵容和关卡跑战斗，检查不变量和跨浏览器一致性。每次 CI 跑固定数量，每晚再跑一大批。

## 理由

不同测试发现不同类型的错误。固定种子让失败可复现。覆盖率门槛进 CI，防止回退。

## 后果

- CI 时间增加；每晚大批量运行承担重的部分。
- 使用 Node 自带的覆盖率统计，依赖 Node 24 起提供的门槛参数。
- 跨浏览器一致性检查见 [0043](0043-ci-gates-and-registry.md)。
