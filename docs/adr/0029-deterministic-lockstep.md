# 0029 确定性帧同步：服务器是时钟，逐帧封口，仲裁复算

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q5, Q13, Q47

## 背景

双人实时合作要两端画面一致、延迟可接受。状态同步要传大量单位数据，且要信任客户端；帧同步只传操作，但要求模拟严格确定（见 [0011](0011-numerics-integer-frames.md)）。

## 决定

- 采用确定性帧同步，30 帧/秒，整数帧。
- 服务器是时钟：每帧到点封口，并广播这一帧的操作。连续的空帧合并发送。
- 客户端只执行已封口的帧。
- 服务器转发操作并用 `@aue/sim` 复算，做仲裁；快照用于重连。
- 运行时结构：主线程画面、后台线程模拟和网络（见 [0009](0009-worker-thread-architecture.md)）。

## 理由

- 只传操作，流量小。
- 服务器做时钟，所有客户端按同一进度前进，不需要客户端之间协商。
- 服务器复算让作弊和断同步都有裁判。

## 后果

- 模拟必须逐位确定，是最大的工程风险，靠一致性检查和每晚大批量测试防护。
- 服务器要跑模拟，有计算成本。
- 输入延迟和追赶见 [0030](0030-input-delay-and-catchup.md)，断同步见 [0031](0031-desync-recovery.md)。

## 备选方案

- 状态同步：计划未采用，流量大且要信任客户端。
