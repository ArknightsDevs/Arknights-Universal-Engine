# 0013 机制模块全部自己重写，只实现官方语义

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q26, Q36, Q37

## 背景

兼容 Stronghold 的接口（见 [0012](0012-stronghold-compatible-core.md)）不等于沿用它的实现。它和官方行为有偏差，代码里有些大函数也难以维护。

## 决定

- 机制模块全部自己重写。
- 只实现官方语义。Stronghold 和官方不一致的地方，登记为已知差异，写明原因（见 [0043](0043-ci-gates-and-registry.md)）。
- 重写顺序：
  1. 纯模块：常量、方向、体积、detmath；
  2. 伤害、状态、索敌；
  3. 技能、职业、AI；
  4. 编排；
  5. 内容。

## 理由

- 先纯函数后有状态，每一层都能用 Stronghold 做差分对照，错误定位更容易（见 [0041](0041-stronghold-differential-testing.md)）。
- 以官方为准，才不会把别人的 bug 继承过来。

## 后果

- 工作量大，但按里程碑逐层交付，每层有完成标准（见 [0051](0051-mvp-scope-and-milestones.md)）。
- "官方语义"依据 PRTS 和数据表，官方不公开的数字只能推断，要登记。

## 备选方案

- 直接沿用 Stronghold 的实现：否决，偏差会被继承，且代码质量不满足可维护性门槛。
