# 0027 遮挡和绘制顺序：照原版

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q65

## 背景

原版里，单位被地形和道具挡住，单位之间有前后关系，特效和界面又在不同层。要得到一致的观感，必须规定各层怎么写深度、怎么排序。

## 决定

| 层 | 行为 |
|---|---|
| 地形、道具、高台 | 不透明，写深度；能挡住单位 |
| 地块高亮 | 做深度测试，写深度 |
| 攻击范围 | 透明，深度略微抬高，避免贴地闪烁 |
| 阴影 | 平贴在地面的半透明片，先于所有单位绘制 |
| 单位 | 透明，做深度测试，不写深度；单位按立在脚下的竖杆计算深度，所以地形和道具能挡住单位；单位之间按离镜头的距离从后往前画 |
| 特效 | 不写深度；是否做深度测试按每个特效材质的设置；前后顺序按排序值 |
| 血条、方向选择器、干员菜单 | 叠加层，清掉深度后画，永远在最上层 |
| 顶栏、部署卡、费用条 | 由 `@aue/ui` 画在页面上 |

- 单位深度基准取单位脚下的高度。这一点运行时的实际取值无法从公开资料确认，登记为推断。
- 渲染代码把"深度换算、绘制排序、遮挡判断"写成纯函数，做单元测试（见 [0048](0048-rendering-tests.md)）。

## 理由

单位不写深度而按脚下竖杆算深度，才能既被地形遮挡，又让相邻单位用距离排序而不互相切割。

## 后果

- 单位之间按距离排序，极端重叠时可能与原版有细微差异。
- 推断项要登记，截图核对后再改（见 [0043](0043-ci-gates-and-registry.md)）。
