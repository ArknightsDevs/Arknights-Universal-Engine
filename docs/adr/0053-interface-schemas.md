# 0053 接口模式集中在 @aue/schema

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q46、Q72、Q73

## 背景

后台线程的模拟、主线程的渲染、服务器三方之间要交换四种数据：

- 渲染状态：每帧一块；
- 表现事件；
- 网络消息；
- 快照。

[0046](0046-versioned-interfaces.md) 要求这些接口都有版本号、有固定样例、有契约测试。如果各自定义在 `@aue/sim`、`@aue/render`、`@aue/net` 里，渲染就得导入模拟才能读懂数据，违反 [0008](0008-module-boundaries.md) 的边界。

## 决定

- 新增 `@aue/schema` 包，不依赖任何包。模拟、帧同步、渲染、后台线程都从这里读格式定义；渲染因此不需要导入模拟。
- **渲染状态（第 1 版）**：一块 `Float64Array`，可以整块转移给主线程，不复制。
  - 帧头：版本、帧号、单位数、玩家数；
  - 每个玩家：生命、费用；
  - 每个单位：编号、种类、归属、x、y、z、朝向、生命、生命上限、动作。
- **表现事件（第 1 版）**：出现、部署、开始攻击、命中、阵亡、到达目标点、撤退。每种事件的字段固定。事件只从模拟流向画面。
- **网络消息（第 1 版）**：
  - 客户端发送：问候、操作、状态哈希；
  - 服务器发送：欢迎（带快照）、封口帧、顺延通知、重新同步、错误。
  - 服务器对客户端消息做**严格校验**：字段必须完全一致，数值必须是范围内的整数，字符串有长度上限；不认识的字段一律拒绝。
- **快照外壳（第 1 版）**：版本、帧号、数据。数据的内部结构归模拟所有，随快照版本一起升级。
- **改格式就升版本**：任何格式改动都要升对应的版本号，并更新固定样例。契约测试把编码结果和固定样例逐项比较，没升版本的改动会让测试失败。

## 理由

格式只定义一份，三方都按它读写。版本号和固定样例让"悄悄改了格式"在 CI 里就暴露出来。

## 后果

- 多了一个包；`tools/layers.json` 里的模拟、帧同步、渲染、后台线程可以依赖它。
- 第 1 版只覆盖骨架用到的内容。部署、撤退之外的指令（技能、倍速、暂停、请求费用）在后续版本里加。
