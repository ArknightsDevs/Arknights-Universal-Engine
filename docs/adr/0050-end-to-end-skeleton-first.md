# 0050 起步后先做端到端骨架

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q73

## 背景

模拟、渲染、数据、帧同步各自推进，接口很容易在合并时才发现不匹配。

## 决定

在起步里程碑（M0）之后插入 M0.5「端到端骨架」：

- 一个关卡、两三个干员，只有部署、移动、普通攻击；
- 用真实的接口跑通：后台线程模拟 → 渲染状态缓冲区和表现事件 → three.js 画面 → 两个浏览器经服务器帧同步 → 快照重连；
- 接口先定型，再往里填实；
- Spine 运行时还没写，单位先用头像做成的卡片代替，不显示没有贴图的东西。

完成标准：两个浏览器能打完一局最小对局；断线后能重连；接口模式有版本号和契约测试（见 [0046](0046-versioned-interfaces.md)）。

## 理由

先把整条链路打通，接口问题早暴露，之后每个模块往里填实。

## 后果

- 骨架里的实现是临时的，接口是长期的，要避免把临时实现当成设计。
- 骨架阶段的单位外观是占位。
