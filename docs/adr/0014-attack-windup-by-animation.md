# 0014 攻击前摇和动画时间：所有单位按动画出伤害

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q54

## 背景

原版里攻击是动画驱动的：动画播到某个时刻才造成伤害。Stronghold 现在只有敌人有前摇，干员的前摇只在画面上处理。

## 决定

- 所有单位都按动画来，包括干员、敌人和召唤物：
  - 冷却到 0 时开始攻击动画，在动画里的攻击时刻（OnAttack）造成伤害或发射投射物；
  - 攻击间隔比动画短时，动画按比例加速；
  - 命中前被眩晕等打断，这次攻击取消。
- 时间数据从 Spine 骨骼提取到数据层（`@aue/spine` 读取，`@aue/data` 生成），计入数据哈希。缺数据的单位用一条登记过的默认规则。
- 部署、阵亡、技能分段：有官方依据的进模拟，没有的只做画面。
- 与 Stronghold 的这个差异登记为已知差异。

## 理由

- 干员前摇影响真实的命中时机和被打断的结果，应当进模拟，才能和原版一致。
- 时间数据进数据哈希，两端数据不同就不能对战（见 [0017](0017-data-pipeline-auto-update.md)）。

## 后果

- 数据流程要读 Spine 骨骼，数据层依赖 `@aue/spine` 的读取部分。
- 攻击动画时长和攻击时刻要和公开来源的帧数据交叉核对（见 [0019](0019-operator-spine-source.md)）。
