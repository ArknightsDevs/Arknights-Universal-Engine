# 0009 模拟放在后台线程，主线程只负责画面

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q42, Q46

## 背景

模拟、WebSocket、状态哈希是持续运算；渲染、输入、界面和音频在主线程。模拟卡顿不应拖垮画面，画面卡顿也不应影响模拟。

## 决定

- 主线程：three.js 画面、`@aue/ui` 战斗界面、输入、音频。
- 后台线程（Worker）：`@aue/sim` 模拟、`@aue/net` 帧同步、WebSocket、状态哈希（每 30 帧）。
- 每个模拟帧，后台线程把紧凑的单位状态写进一块 ArrayBuffer，转移给主线程；同时附上这一帧的表现事件（开始攻击、命中、技能开关、部署、阵亡、特效）。
- 主线程在最近两帧之间插值。
- 表现事件只从模拟流向画面，不计入状态哈希，但计入一致性检查的"画面"层。
- 不用 SharedArrayBuffer，所以不需要 COOP / COEP 响应头。

## 理由

- 转移 ArrayBuffer 不复制，开销小。
- 不用 SharedArrayBuffer 让部署不受跨源隔离响应头约束。

## 后果

- 画面与模拟之间有一帧左右的延迟，靠插值掩盖。
- 缓冲区布局和事件格式是契约，要版本化（见 [0046](0046-versioned-interfaces.md)）。
- 需要一个端到端骨架尽早验证这条链路（见 [0050](0050-end-to-end-skeleton-first.md)）。

## 备选方案

- 模拟放在主线程：否决，会和渲染争用。
- SharedArrayBuffer：否决，需要特殊响应头。
