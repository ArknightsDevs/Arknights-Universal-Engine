# 0017 数据流程：定时自动更新，可复现，握手比对数据哈希

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q10, Q20

## 背景

游戏数据会随版本更新。手工更新容易遗漏，也无法发现更新带来的行为变化。

## 决定

| 数据 | 来源 | 处理 |
|---|---|---|
| 关卡、角色、技能、敌人等 | ArknightsGameData | 定时任务：重新生成数据，跑黄金结果，带着差异提交 |
| 每关的镜头位置 | [ArknightsGameResource](https://github.com/yuanyan3060/ArknightsGameResource) 的 `map.json`（AGPL-3.0） | 构建时拉取并提取成镜头表，注明出处（见 [0026](0026-camera-model.md)） |
| 攻击动画时间 | Spine 骨骼 | 提取动画时长和攻击时刻，和公开来源的帧数据交叉核对（见 [0014](0014-attack-windup-by-animation.md)） |

- 构建可复现。
- 握手时比对数据哈希：数据不同的两端不能对战。
- 所有下载来的数据都当作不可信数据处理：用严格解析器，设大小上限，绝不执行。

## 理由

- 带差异的提交让每次数据更新对行为的影响可见、可审查。
- 数据哈希握手防止两端数据不一致导致断同步。
- 外部数据可能出错或被篡改，必须当作不可信输入。

## 后果

- 需要定时任务和黄金结果的维护。
- 数据更新可能导致黄金结果变化，需要人工审查差异。
- `map.json` 是 AGPL-3.0，提取的镜头表要注明出处。
