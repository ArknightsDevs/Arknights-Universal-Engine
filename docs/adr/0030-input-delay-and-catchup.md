# 0030 输入延迟固定 9 帧，落后时最多 5 倍速追赶

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q30, Q47, Q52

## 背景

客户端发出的操作要等服务器封口才能执行。需要一个固定的提前量，让操作能赶上封口，又不让手感太迟钝。

## 决定

- 执行帧 = 本地最新帧 + 9。固定 9 帧（0.3 秒），对应官方的 `maxOperatorDelay` 0.3。
- 服务器收到操作时：
  - 那一帧没封口：照收；
  - 已封口：顺延到下一个没封口的帧，并通知发送者。
- 客户端落后时最多用 5 倍速追赶，对应官方的 `maxPlaySpeed` 5。
- 断线重连时用快照加快进。
- 延迟超过 200 ms 时提示网络不适合（Q52）。

## 理由

固定延迟简单、可预测，数值直接来自官方参数。

## 后果

- 每个操作有约 0.3 秒的执行延迟，是已知代价。
- 网络差的玩家会反复追赶或被顺延。
- 追赶的速度上限影响重连后的体验。
