# 0037 mod：先做数据 mod，官方内容注册为内置 mod

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q4, Q17, Q38

## 背景

我们要支持社区扩展，但脚本 mod 的安全和确定性风险高。先支持数据 mod，且让官方内容走同一套机制，既能验证注册表，又避免官方内容成为特例。

## 决定

- 先做数据 mod；官方内容本身注册成内置 mod `official`。
- 注册表从第一天起就有，加载器放在 MVP 之后。
- 清单格式：沿用并扩展 Stronghold 的包清单和规则。
- id 规则：官方 id 不变，mod 内容加 `modid:` 前缀。
- mod 以补丁方式覆盖已有内容，按依赖和优先级给出冲突警告。
- 对局标记：握手时比对内容哈希；装了 mod 的对局加标记。
- 黄金结果、一致性检查、兼容检查都只跑原版内容。
- 脚本 mod 见 [0038](0038-script-mod-rewriting.md)，mod 素材见 [0039](0039-mod-assets.md)。

## 理由

- 官方内容走同一套注册表，机制从第一天起被真实使用。
- 前缀避免 id 冲突；补丁式覆盖让多个 mod 可以叠加。
- 检查只跑原版，保证基线稳定。

## 后果

- 加载器要等 MVP 之后。
- 内容哈希不同的两端不能同局，装 mod 的对局要明确标识。
- 冲突警告的规则要持续打磨。
