# 0055 SDK：现在只做准备，MVP 之后再做

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q77、Q78、Q79、Q80

## 背景

AUE 以后会有三类外部用户：

- mod 作者：数据 mod 和脚本 mod；
- 玩法插件作者：常规项目之外的新模式；
- 外部项目：争锋频道换用我们的 Spine 运行时，Stronghold 共用一致性检查。

他们都需要稳定的接口。但 M3、M4 还会改内部结构（M2 刚换掉了单位字段），现在就承诺接口稳定，以后每次改动都是破坏性变更。

## 决定

- **SDK 面向全部三类用户**（Q77）。
- **现在只做准备，SDK 本身和 MVP 之后的数据 mod 加载器一起做**（Q78）。准备工作有三件：
  1. **接口按将来给 mod 用来设计**：从 M3 起，技能、天赋、Buff 行为这类内容接口以数据为主，沿用官方数据表的结构（如 skill_table 的 blackboard）。行为按键注册，只拿到受限的上下文，不能直接改世界状态。接口带版本号（[0046](0046-versioned-interfaces.md)）。
  2. **公开面就是包的入口**：每个包 `package.json` 的 `exports` 只开放 `src/index.js`（`@aue/content` 另外开放它的数据文件），入口导出的就是公开接口。以后脚本 mod 的映射表也只映射公开接口（[0038](0038-script-mod-rewriting.md)）。
  3. **类型定义进 CI**：`pnpm run types` 从 JSDoc 生成全部包的 `.d.ts`（`tsconfig.types.json`，输出到 `.cache/types`，暂不发布）。公开类型写不出声明时，CI 失败。
- **脚本 mod 用原生接口，同时保留 Stronghold 兼容层**（Q79）。原生接口按上面第 1 条设计；兼容层（[0012](0012-stronghold-compatible-core.md)、[0045](0045-unit-field-ownership-compat-isolation.md)）只用来加载已有的 kit。
- **MVP 之后把 `@aue/*` 发到 npm**（Q80）：版本号遵循语义化版本，由你的账号发布。争锋频道换用 Spine 运行时时先发 `@aue/spine`。平台仍以子模块引用引擎（[0052](0052-engine-as-git-submodule.md)）。

## 理由

- 准备工作的成本很低，又能避免以后为了开放接口而返工：内容接口一开始就按 mod 接口来设计，就不会先长成只供内部使用的样子。
- 等 MVP 之后再承诺稳定，接口已经经过真实内容和真实对局的检验。
- 原生接口受限、带版本，mod 就不会依赖内部细节；兼容层让现有 kit 不用改写就能使用。

## 后果

- MVP 之后的 SDK 包括：`aue` 命令行（mod 的创建、检查、测试、打包），内容和清单的 JSON 模式，文档和模板，npm 包。
- 玩法插件接口等到有第二个模式时再定型，在那之前只在平台内部使用。
- 每个包的入口要保持干净：只为测试存在的导出不放进入口。
