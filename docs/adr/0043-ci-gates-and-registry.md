# 0043 三道 CI 关卡与已知差异登记表

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q27, Q72

## 背景

我们同时依赖 Stronghold 的内容、官方行为和自己的跨引擎确定性。要有一套关卡来分别守住，并且推断和差异不能散落在代码注释里。

## 决定

三道 CI 关卡：

1. Stronghold 的内容测试；
2. 黄金结果比较（行为等价，见 [0041](0041-stronghold-differential-testing.md)）：整场战斗摘要的差异必须登记原因；
3. 我们的跨引擎一致性检查：Chromium、Firefox、WebKit，在 ubuntu 和 macOS 上跑。

已知差异登记表：

- Stronghold 的偏差、推断得来的官方数字、镜头和遮挡里的推断，都登记在这里，每条写明依据。
- 登记成 JSON（`docs/registry/`，不引入 YAML 解析的依赖），每条有编号、对应条款、依据和状态，由 `aue-check registry`（`@aue/testkit`）检查。

CI 还跑：lint、类型检查、测试和覆盖率、规范追溯、登记表、共享文件比对；在 ubuntu、windows、macOS 上，各跑 Node 22 和 24。

## 理由

三道关卡各守一件事：内容兼容、行为等价、确定性。登记表把"我们知道这里不一样"变成可检查的数据。

## 后果

- 每个差异都要有人写依据，增加维护成本。
- 一致性检查跨浏览器、跨系统，耗时长。
- 登记表里的推断项应当随证据出现而被修正或关闭。
