# 0051 MVP 范围与里程碑

- 状态：已采纳
- 日期：2026-10-11
- 来源：规划讨论 Q31, Q73, Q71

## 背景

范围很大。模拟、渲染、数据三条线可以并行；帧同步依赖模拟；MVP 把它们合起来。

## 决定

| # | 里程碑 | 完成标准 |
|---|---|---|
| M0 | 起步：仓库骨架、工作区、lint 边界规则、映射表生成器、三道 CI 关卡的空架子、许可文件、NOTICE、免责声明；实测"标签 + 子目录"引用 | CI 全绿；平台能从 git 标签装上引擎的子包 |
| M0.5 | 端到端骨架（见 [0050](0050-end-to-end-skeleton-first.md)） | 两个浏览器能打完一局最小对局；断线后能重连 |
| M1 | 纯模块：`@aue/math`、常量、方向、体积 | 和 Stronghold 逐位一致；分支覆盖率 ≥95%；条款全部可追溯 |
| M2 | 伤害、状态、索敌 | 同上，加上不变量和变换测试 |
| M3 | 技能、职业、AI，包括按动画的攻击前摇 | 同上；和 Stronghold 的差异都已登记 |
| M4 | 编排和内容：战斗循环、多玩家能力、指令、快照、状态哈希；通过映射表加载 Stronghold 的 kit | 通过 Stronghold 内容测试；黄金结果的差异都已登记；三个浏览器一致 |
| M5 | 数据流程 | 构建可复现；抽样骨骼与来源一致 |
| M6 | Spine 运行时 | 和 spine-ts 3.8 的姿态、顶点对照通过（维护者本机可选）；截图核对通过 |
| M7 | 渲染：场景生成、镜头、遮挡、阴影、单位、特效播放器移植、叠加层、`@aue/ui` 还原战斗界面 | 投影和截图对得上；遮挡规则和原版一致；PC 和手机上的帧率、显存实测达标（预算在 M7 定） |
| M8 | 帧同步：后台线程、服务器时钟和封口、追赶、快照、断同步报告、服务器仲裁复算 | 机器人对局、断线重连、人为制造断同步并恢复，都通过 |
| M9 | MVP：常规项目插件；MVP 关卡和干员；复用争锋频道的局域网大厅和房间；本地存档、box 录入；攻击、命中特效；音频 | 两人局域网能完整打完一局两关；CI 三道关卡全绿；发布 v0.1.0（由维护者账号发布） |

MVP 内容：

- 2–3 个关卡，按敌人覆盖面挑选。在 M9 前先做覆盖分析，再选定。
- 干员：Stronghold 的 72 个六星；通用机制能覆盖的三到五星；5 个预备干员。
- 只做常规项目（见 [0033](0033-coop-rules-follow-prts.md)）。

MVP 之后，依次做：数据 mod 加载器；账号和 SSO；其他模式（堡垒守御、足球、漂航）。

穿插进行：技能特效分批加入；语音和缺的音效；box 导入；素材 CDN；活动进度系统；按实测决定是否引入 KTX2（见 [0020](0020-texture-format-webp.md)）；争锋频道换用引擎的 Spine 运行时。

## 理由

三条线并行缩短周期；每个里程碑有可检查的完成标准；MVP 把范围收到"两人局域网打完一局两关"。

## 后果

- 手机和 PC 的性能预算要到 M7 才定。
- MVP 关卡尚未选定。
- 缺失的音频、技能特效、进度系统都留在 MVP 之后。
