# 0067 伤害结算的来源、计算阶段与伤判观察接口

- 状态：已提议
- 日期：2026-10-25
- 来源：Stronghold Protocol 0.3.2 结算重构的迁移提案；AUE main `e727f5cc3531056990fe2d323a27697e8d55bee4` 源码审阅

## 背景

AUE 已有伤害公式、有序 Buff 伤判、来源为空但保留归属的处理，以及特殊生命值只改变 HP 扣除量的实现。本提案补充这些能力之间的接口契约，不重写整套战斗内核。

当前主入口以 source 与伤害描述符传递上下文。`sourceless` 能抑制来源效果并保留归属，但不直接表达实际来源与归属任意不同的情况。计算入口主要走同一条公式路径；预计算与计算后伤害需要明确哪些阶段已经完成。伤判中剩余金额归零即退出，正值 `take` 行为不能单独表达取消后的合法观察。

这些差异会影响缓存攻击力、追加伤害、反伤、特殊生命值上的回复基数和受伤计数。补能力时必须继续遵守纯数据 Buff、内容兼容隔离、确定性和现有死亡阶段。

本文提出接口边界。机制数值、具体技能和取消条件仍以带来源的规范及测试决定；Stronghold 的实现与一致性不是官方规则的替代证据。

## 决定

以下为待评审的决定。接受本 ADR 不表示全部分项已经实现。

### 结算上下文中的概念分别表达

主结算能力能够独立表达：

| 概念 | 契约 |
|---|---|
| 实际来源 source | 读取来源属性、来源条件和来源事件的实体，可为空 |
| 归属 credit | 统计与击杀归属；省略默认 source，显式 null 保持为空；不赋予来源能力 |
| HP 伤害类型 | 物理、法术、真实、元素 HP 伤害；不与元素槽操作混淆 |
| 原生攻击类型 | 普通、溅射、持续、附加等原生分类；独立于标签与是否完整攻击 |
| 实例途径 | 本次伤害的近战/远程等途径；来源自身的攻击方式仍是另一项条件 |
| 计算阶段 | 基础输入、预计算输入、计算后输入 |

字段名以实现评审结果为准。旧调用的标签/布尔值推导集中在兼容边界；显式新请求不从 `dot/counter/reflect` 等描述标签猜原生类型。完整攻击负责弹药、攻击 SP 与攻击事件，伤害入口不额外执行一次完整攻击。

### 明确计算阶段已经完成的工作

| 输入阶段 | 来源计算 | 目标计算与防御/抗性 | 后续输出、施加与伤判 |
|---|---|---|---|
| 基础 | 有实际来源时执行 | 执行 | 执行 |
| 预计算 | 跳过 | 执行 | 执行 |
| 计算后 | 跳过 | 跳过已完成的计算 | 执行 |

输入金额包含哪些攻击倍率、计算后输入跳过哪些来源倍率、实例倍率的应用次数，必须由规范和数字用例共同说明。预计算不自动代表无来源、不可闪避或不受目标修正影响。

计算和施加之间保留可区分的来源输出、来源施加前、目标施加中时点。已经算出的金额不因施加前改变 DEF 而重新计算；后续伤判读取允许在该阶段变化的当前状态。内容迁入新阶段时移除原路径的同一效果，防止重复生效。

### 伤判修改与伤判观察分开

继续按优先级、实际获取顺序处理生效 Buff。原生行为保存在行为表中，Buff 只保存数据与行为键。

修改行为能改变金额、消耗资源和尝试取消；观察行为读取本位置的金额和结果。前序效果取消/归零后，后序普通防御不再消耗资源或抽随机数，符合自身条件的观察行为仍可在原位置执行。观察载荷的修改不能复活或增加该实例伤害。

早期拒绝或在伤判之前取消的实例不进入伤判观察。观察资格必须按具体机制的条件定义，不能把所有钩子无条件广播。已经在本轮被移除的 Buff 不继续执行；重入及清理沿用总线既有约束。

### 尝试结果与取消是否成功分开

保留跳过某种判定的能力，并另行表达某类取消不能生效。跳过闪避时不进行该次随机判定；允许尝试但屏蔽取消时，仍执行规则要求的概率、次数消耗和尝试事件。

闪避、抵挡、落空分别记录。部分屏障只减小伤害，不因“抵挡取消被屏蔽”恢复被吸收的那部分。该策略不绕过无敌、失效目标或其他未列明的拒绝条件。

新增能力默认保留旧输入行为。若需要改变合并概率与逐层抽样等 RNG 契约，单独提供机制依据、序列测试和差分记录。

### 结算结果与实际 HP 变化分开

结果能够同时表达当前结算金额、实际 HP 变化、操作种类和取消/归零结果。正值普通伤害成功、调整值施加成功、实际 HP 变化提供各自资格，不复用一个含糊的受伤通知。

特殊生命值沿用当前正确的数值分离：结算金额可以为正，实际 HP 只减 1 或不减。屏障完全吸收与特殊 HP 不接受该类型不得混为同一种成功结果。普通治疗、属性回复、直接恢复、元素槽施加/恢复和生命流失保留各自的事件资格。

保留旧入口数值返回值；扩展通过新入口、内部结果或新事件表达，不在一次接口重构中改写旧消费者的返回值语义。旧通知维持历史契约，新内容使用更精确时点。

### 保留帧末死亡与纯数据恢复

本提案不把 Stronghold 的同步击杀流程引入 AUE。需要目标完成死亡处理后才判断的条件后续，明确安排在 AUE 的既有死亡阶段之后。

跨阶段/跨帧待执行数据保存实体 id、行为键、帧和金额；不把闭包、函数或单位引用放进持久 World。归属实体离场后的识别和统计需要稳定数据设计与测试，不从当前存活单位推断。

瞬时调用的临时上下文可以持有引用。兼容 kit 的闭包留在 compat，继续遵守已有从头重放契约；新原生状态必须加入快照和状态哈希覆盖。

### 分步提交并保持边界

每个实现 PR 只引入一个可验证能力及必要消费者/测试，附规范、来源和预期差分。已具备的穿透顺序、有序伤判和特殊 HP 映射继续沿用。

兼容层统一适配新旧入口，但原生 sim 不导入 Stronghold 模块。先完成所需能力与内容，再单独更新固定 kit 提交、允许名单、oracle、差分与内容身份。固定版本不改成浮动分支。

不在本 ADR 中决定卫戍专属限伤、共享血池、羁绊分担组合、碎铳之簧的 Boss 选择、Boss 技能调度或新的表现格式。

## 理由

正交信息让同一项机制在正确条件与时点生效，避免通过标签、统计归属或最终扣血反推过程。明确预计算边界可防止派生伤害再次触发来源计算；按位置观察则能表达伤害被防御挡住后的反击和计数。

以 AUE 原生行为表实现这些契约，可以保留现有数据、恢复和包依赖边界。旧接口集中转换，允许内容逐步迁移，不要求同时重写全部干员。

## 后果

- 新事件与字段增加维护成本，需要逐项规范、契约和内容覆盖，不能只靠整局结果验证。
- 合法规则修正可能改变事件顺序、RNG 与整局结果；只登记有依据的差异，不把新结果一律当成正确基线。
- 需要审阅已有原生天赋和 compat 的执行位置，防止迁移后重复计算。
- 若改变行为上下文、快照或表现格式，按实际受影响接口更新版本与 fixture；不一律增加所有版本。
- 固定减免、屏障生命周期、分担与治疗的具体规则随各自实现评审，不由本 ADR 一次裁定。
- 不承诺运行速度提高。性能另用固定输入测量；纯兼容重构需验证旧 HP、资源、事件、返回值与 RNG 不变。

## 备选方案

1. **直接复制 Stronghold 的 attack 目录。** 不选：依赖战斗类、函数 Buff、同步死亡与专属玩法，破坏 AUE 的状态及包边界。
2. **所有能力继续挂在 hit/damaged。** 不选：无法区分计算、施加、观察与成功，容易重复触发或错过取消后的效果。
3. **一次升级全部 kit，再补兼容缺口。** 不选：载入成功不能证明机制正确，容易隐藏原生回退与阶段缺失。
4. **完全不兼容，先重写所有内容。** 不选：当前迁移成本过高；原生接口与兼容层可以共同使用相同结算能力。
