# 0057 内核的钩子总线与定时器

- 状态：已采纳
- 日期：2026-10-12
- 来源：E2 选定走兼容层（2026-10-12），ADR 0012、0045、0054

## 背景

Stronghold 的 kit 通过钩子总线（`battle.on` / `emit`）和定时器（`after` / `every`）接入战斗：伤害、死亡、部署、技能开关、每帧末等时点都有事件，处理函数可以改写上下文（取消命中、改伤害倍率、阻止致死）。我们的 Buff 是纯数据（ADR 0054），内核里没有这样的扩展点；兼容代码又不能进内核（ADR 0045）。

## 决定

- 内核提供一条通用的钩子总线和以帧计的定时器（`packages/sim/src/bus.js`）：登记、按优先级与登记先后发出、停止传播、嵌套上限、按所有者移除；若干帧后、每隔若干帧。
- 内核在一帧的固定位置发出具名事件，上下文可被处理函数改写；事件名沿用 Stronghold 的，兼容层把上下文转成它的形状。事件点按兼容层的需要逐步加入，每个都写进规范（钩子-3）。
- 处理函数和定时器不是状态：不进状态哈希，不进快照。用到它们的内容在断线重连和断同步恢复时，不能只靠快照恢复——改为从头重放（计划 E1f）。
- 处理函数出错时怎样隔离由兼容层决定，内核只负责按顺序调用。

## 理由

钩子是内容代码接入战斗最通用的方式，Stronghold 的 72 个 kit 都依赖它；放在内核里是一个中立的扩展点，不含任何兼容代码。以帧计时与时间-1、时间-2 一致。

## 后果

- 内核的伤害、治疗、状态、技能、部署、死亡等流程要在相应位置发出事件，并接受上下文的改写。
- 快照恢复对用到钩子的内容不再完整，需要重放。
- 事件点越多，内核与 Stronghold 的事件语义越要对齐；不一致处登记差异。
