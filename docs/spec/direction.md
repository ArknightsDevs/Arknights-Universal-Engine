# 方向

函数名和 Stronghold Protocol 的内容接口一致（ADR 0012），方便沿用它的 kit。网络消息和渲染状态里用数字编码（ADR 0053 的 `DIR`），进入模拟时换成名字。

### 方向-1 四个方向

- **名字和前方**：方向是 `UP`、`RIGHT`、`DOWN`、`LEFT`，默认 `RIGHT`。第 0 行是离镜头最近的一行（地图-1），所以 `UP` 是行号增大的方向。
  - 前方向量记作 [行差, 列差]：UP (1, 0)，RIGHT (0, 1)，DOWN (−1, 0)，LEFT (0, −1)。
- **换算规则**：
  - 名字不分大小写，首尾空白忽略；
  - 旧式的朝向符号：负数为 `LEFT`，正数为 `RIGHT`；
  - 其他值取给定的默认值，默认值本身无效时取 `RIGHT`。
- **派生的几个关系**：
  - 相反方向：UP↔DOWN、RIGHT↔LEFT；
  - 镜像：RIGHT↔LEFT，UP、DOWN 不变；
  - 垂直：两个前方向量的点积为 0；
  - 水平翻转符号：`LEFT` 为 −1，其余为 +1。
- **协议编码**：RIGHT 0、UP 1、LEFT 2、DOWN 3（ADR 0053）。

- 来源：方向和坐标见 数据：level.routes[].startPosition（行号自下而上，地图-1）；换算规则与 Stronghold 内容接口一致，设计决定见 [ADR 0012](../adr/0012-stronghold-compatible-core.md)

### 方向-2 偏移随朝向旋转

攻击范围等相对偏移 [行差 dr, 列差 dc] 以面朝右书写，列差是前方。面朝其他方向时旋转：

| 朝向 | 绝对偏移 |
|---|---|
| RIGHT | (dr, dc) |
| UP | (dc, −dr) |
| LEFT | (−dr, −dc) |
| DOWN | (−dc, dr) |

- 每次逆时针转四分之一圈：面朝右时的左手边（dr > 0），面朝上时变成左边。
- `toLocal` 是它的逆运算。
- 结果里不出现 −0：取负写作 `0 − x`。

- 来源：数据：range_table.grids（以面朝右书写）；dr > 0 在左手边这一约定为推断 INF-0013

### 方向-3 由位移得到方向

位移 (行差, 列差) 的方向取绝对值较大的那一轴，相等时取水平方向。位移为零时取给定的默认值。非数字按 0 处理。

- 来源：设计决定，与 Stronghold 内容接口一致，见 [ADR 0012](../adr/0012-stronghold-compatible-core.md)

### 方向-4 并列时的先后

在"取第一个格子"之类的选择里，一个格子相对单位的先后，取它的位移在单位面朝右坐标系中的值（`toLocal`），按 (行, 列) 字典序比较，小的在先。面朝右时就是 (行, 列) 的顺序。

- 来源：设计决定，与 Stronghold 内容接口一致，见 [ADR 0012](../adr/0012-stronghold-compatible-core.md)；官方并列规则待查（M2 索敌时核实）
