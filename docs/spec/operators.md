# 干员的练度

玩家的干员带着练度出战：精英化阶段、等级、潜能、信赖、技能和技能等级。实现见 `packages/data/src/operators.js`（提取）和 `packages/content/src/operators.js`（按练度组装）。

### 干员-1 属性

按练度算干员的基础属性（属性-1 的基础值）：

1. **精英化与等级**：取精英化阶段的属性关键帧（数据里每个阶段是 1 级和满级两帧），在两帧之间按等级线性插值，不取整。等级限制在 1 到这个阶段的满级之间。
2. **信赖**：信赖加成的关键帧是信赖等级 0 和 50（信赖 100%），信赖 0%–100% 之间线性插值，超过 100% 按 100% 算，加到上一步的结果上。
3. **潜能**：潜能 n（1–6）应用前 n − 1 个潜能提升里的属性修正，都是直接加算：`COST` 部署费用、`RESPAWN_TIME` 再部署时间、`ATK` 攻击、`DEF` 防御、`MAX_HP` 生命、`ATTACK_SPEED` 攻击速度、`MAGIC_RESISTANCE` 法术抗性。

攻击范围取这个精英化阶段的范围。

- 来源：[PRTS「游戏数据基础」oldid=440563](https://prts.wiki/index.php?title=%E6%B8%B8%E6%88%8F%E6%95%B0%E6%8D%AE%E5%9F%BA%E7%A1%80&oldid=440563) 页面注释中的属性计算器说明：「影响属性计算器运算结果的因素有：精英化阶段、等级、潜能等级和信赖值」「根据精英化阶段和等级两个属性计算出第二步运算所需的属性数值」「通过信赖表格获得信赖值所对应的信赖等级，按照该干员定义的信赖加成数值和上一步运算的结果，计算出第三步运算所需的属性数值」「附加上潜能给予的属性（通常为直接加算）」；[PRTS「信赖值」oldid=430483](https://prts.wiki/index.php?title=%E4%BF%A1%E8%B5%96%E5%80%BC&oldid=430483)「干员信赖值达到100%后，属性加成达到上限」；数据：character_table 的 phases[].attributesKeyFrames、favorKeyFrames、potentialRanks；线性插值不取整、信赖等级 50 即 100% 为推断 INF-0078

### 干员-2 技能与技能等级

干员带一个技能（第几个技能，从 0 数）出战，技能等级 1–7，专精 1–3 记作 8–10，取 skill_table 中这个技能的第（等级 − 1）级数据（技能-1）。精英化阶段低于技能的解锁阶段时不能带这个技能；技能没有那么多级时取最后一级。技能能否主动关闭（技能-7）、技能期间的攻击范围（技能-8）也按这一级的说明和范围编号判断；训练数据的每一级记录说明原文（`description`）和范围编号（`rangeId`，没有为 null）。

- 来源：数据：character_table 的 skills[]（skillId、unlockCond.phase）、skill_table[].levels[]；[PRTS「游戏数据基础」oldid=440563](https://prts.wiki/index.php?title=%E6%B8%B8%E6%88%8F%E6%95%B0%E6%8D%AE%E5%9F%BA%E7%A1%80&oldid=440563)「专精3等级的推进之王碎颅击」等写法；专精记作 8–10 是设计决定

### 干员-3 特性的练度

分支特性的 blackboard（职业-7）取特性候选中已经解锁的最后一个：解锁阶段不高于干员的精英化阶段（同一阶段时解锁等级不高于干员等级），需要的潜能不高于干员的潜能。没有特性记录的干员 blackboard 为空。候选带范围编号时一并记作 `rangeId`（散射手的 1-3，傀儡师替身的范围，职业-16），没有时不写。

- 来源：数据：character_table 的 trait.candidates[]（unlockCondition.phase、unlockCondition.level、requiredPotentialRank、rangeId、blackboard）；取最后一个已解锁的候选为推断 INF-0079

### 干员-4 天赋

干员的天赋按 character_table 里 talents 的顺序记录，每个天赋是它的候选列表（talents 为空，或某个天赋没有候选时，对应为空列表）。每个候选记录：解锁的精英化阶段（`PHASE_n` 记作 n）和等级，需要的潜能（0–5），名称、描述（原文，富文本标签保留）、范围编号 `rangeId`（没有为 null），blackboard，以及它是哪一个天赋 `prefab`（prefabKey，没有为 null；模组的天赋部件用它指明改的是哪个天赋，干员-7）。候选的解锁条件和特性候选一样（干员-3）。

blackboard 里的数值条目记作 `{ 键: 值 }`；带 `valueStr` 的条目是文本（它的值只是占位），另记作 `text: { 键: 文本 }`，没有文本条目时不写 `text`。同一个候选里键重复时报错。

`isHideTalent` 为真的候选是不在干员信息里展示的天赋（名称和描述为空，多半带着召唤物或模组用的数据，`token` 记 `tokenKey`），也照样保留，用 `hidden: true` 标明，由使用方决定是否展示。

- 来源：数据：character_table 的 talents[].candidates[]（unlockCondition.phase、unlockCondition.level、requiredPotentialRank、name、description、rangeId、blackboard[].key/value/valueStr、isHideTalent、tokenKey、prefabKey）；保留隐藏天赋、文本条目另记是设计决定

### 干员-5 模组

干员的模组取 uniequip_table 的 `charEquip[干员 id]` 里列出的、在 battle_equip_table 里有战斗数据的那些，按 charEquip 的顺序；初始的「证章」没有战斗数据，不记录。模组的 `charId` 必须是这个干员，否则报错。每个模组记录：编号、名称（uniEquipName）、类型（`typeName1` 和 `typeName2` 以 `-` 连接，如 `SUM-X`，没有 typeName2 时只有 typeName1）、解锁的精英化阶段（unlockEvolvePhase）和等级（unlockLevel），以及每一级（battle_equip_table 的 phases[]，`equipLevel`）的内容：

1. **属性加成** `stats`：attributeBlackboard 里每个键加到干员属性上，用引擎的属性名（属性-1）：`max_hp`→`maxHp`、`atk`→`atk`、`def`→`def`、`attack_speed`→`aspd`、`magic_resistance`→`res`、`cost`→`cost`、`respawn_time`→`respawnTime`、`block_cnt`→`blockCnt`、`base_attack_time`→`baseAttackTime`。不在这个表里的键报错，不丢弃。
2. **召唤物的属性加成** `tokens`：tokenAttributeBlackboard 按召唤物 id 分开记录，键用同一张表，再加 `max_deck_stack_cnt`→`maxDeckStackCnt`、`max_deploy_count`→`maxDeployCount`（可同时部署的数量，引擎还没有对应的属性）。
3. **部件** `parts`：每个部件记录目标 `target`（`TRAIT`、`TRAIT_DATA_ONLY`、`DISPLAY`、`OVERWRITE_BATTLE_DATA`、`TALENT`、`TALENT_DATA_ONLY`，其他值报错）、是否属于召唤物 `token`（isToken）、只在哪种游戏模式和地图标签下有效（`gameTag`、`mapTag`，没有限制为 null）。部件的特性候选 `trait` 记：解锁阶段、等级、潜能、追加描述 `add`（additionalDescription）、替换描述 `override`（overrideDescripton，数据里就这样拼）、`rangeId`、blackboard（写法同干员-4）。部件的天赋候选 `talents` 记：`index`（talentIndex：显示在第几个天赋上，从 0 数；−1、−2 是模组自己带的天赋）、`prefab`（prefabKey：它是哪一个天赋，同干员-4，没有为 null）、解锁阶段、等级、潜能、名称、升级描述 `upgrade`（upgradeDescription）、`rangeId`、blackboard、`hidden`、`modes`（validModeIndices，没有为 null）。描述都是原文。

这里只记录数据，模组怎样改变干员由使用方决定。`DISPLAY` 部件只有展示用的特性说明，`TRAIT` 和 `TRAIT_DATA_ONLY` 覆盖特性数据，`TALENT` 和 `TALENT_DATA_ONLY` 增加或覆盖天赋数据，`OVERWRITE_BATTLE_DATA` 的 blackboard 全是文本条目；这些含义是按目标名字做的推断，没有逐一核对。阿米娅的转职形态（char_1001_amiya2、char_1037_amiya3）不在 character_table 的干员里，它们的模组不记录。

- 来源：数据：uniequip_table 的 charEquip、equipDict[]（uniEquipName、typeName1、typeName2、unlockEvolvePhase、unlockLevel、charId）；battle_equip_table[].phases[]（equipLevel、attributeBlackboard、tokenAttributeBlackboard、parts[].target/isToken/validInGameTag/validInMapTag/overrideTraitDataBundle.candidates[]/addOrOverrideTalentDataBundle.candidates[]）；键的对应关系和 `maxDeckStackCnt`、`maxDeployCount` 两个名字是设计决定

### 干员-6 天赋的练度与常驻部分

每个天赋在一个练度下取它最后一个已解锁的候选，解锁条件同特性（干员-3）；没有已解锁候选的天赋不生效。装备模组时，模组可以把天赋换成它的升级（干员-7）。

天赋的**常驻部分**从部署起一直生效。描述去掉富文本标签和全角括号里的潜能差值、去掉末尾的「。」「；」后，取第一句（到第一个「。」或「；」为止），从第一个分句（以「，」分开）起数连续的**自身属性分句**，至少要有一个：

- 自身属性分句是「（但）（自身/自身的）属性（和/、属性）（各）带符号的数值（%、秒、/秒）」；
- 属性词和 blackboard 键的对应：攻击力 `atk`，防御力 `def`，生命上限、最大生命值、生命值 `max_hp`，攻击速度、攻速 `attack_speed`，法术抗性 `magic_resistance`，技力自然回复速度 `sp_recovery_per_sec`，再部署时间 `respawn_time`，部署费用 `cost`；
- 这些分句提到的键都在 blackboard 里，常驻部分就是这些键和它们的值；
- 描述只有这些分句时，blackboard 里其他键的值都要是 0；后面还有内容时，第一句里剩下的部分不能提到「效果」（它可能改变前面的加成，如「自身受到伤害后失去该效果」「……时效果翻倍」）；
- 隐藏候选（干员-4）没有常驻部分。

例：「攻击速度+6」整句常驻；「攻击力+8%，攻击变为弱点伤害」的攻击力加成常驻，弱点伤害不在这里；「攻击力+6%，生命上限+10%。置入战场后这个效果会同样赋予给一名随机友方单位」的第一句是干员自己的常驻加成；「部署后随机永久获得下列一项增益：……」「攻击速度+10，自身受到伤害后失去该效果」没有常驻部分。

各天赋的常驻部分按键相加（值为 0 的键略去）：`cost` 加到部署费用、`respawn_time` 加到再部署时间（都不低于 0），其余的键作为干员的 `talentBb`，部署时成为 Buff（部署-4）。常驻部分的分句也可以是不属于属性的效果（干员-16），它们不进 `talentBb`；属性分句也可以倒着写（「获得+18%攻击力」）。后面的句子说「效果翻倍」时（「……后效果翻倍」）不算常驻部分。

**按所带技能分段**：描述（去掉标签和潜能差值后）是几段、每段以「装备技能N时」开头（在每个「装备技能N时」之前、「，」或「；」处分开）时，只取所带技能（第 N − 1 个技能）那一段、去掉这几个字，blackboard 去掉其他段用到的键（属性词指的键和 干员-16 的效果用的键；本段也用到的保留）；没有对应的段时照原样。所有读取天赋的部分（干员-6、干员-9、干员-11…干员-19）都按分段后的天赋读。

天赋的其余内容（干员-9、干员-11…干员-19 读不了的）还没有实现。

- 来源：数据：character_table 的 talents（干员-4）；按描述判定常驻部分、和技能的属性加成同样换算为推断 INF-0088；部署费用的增减在费用倍率之前：[PRTS「部署费用」oldid=434779](https://prts.wiki/index.php?title=%E9%83%A8%E7%BD%B2%E8%B4%B9%E7%94%A8&oldid=434779)「部署费用（属性）=(初始部署费用+基础费用增减)×费用倍率+实时费用增减」

### 干员-7 模组的练度

练度可以带一个模组：`module` 是干员模组列表（干员-5）里的序号（从 0 数，−1 或不写表示不带），`moduleLevel` 是模组等级 1–3（超过模组的等级数时取最后一级，不写为 1）。模组要在它的解锁精英化阶段和等级之后才能带，否则报错。

- **属性**：模组这一级的属性加成 `stats` 和潜能一样加到原始属性上（在潜能之后）。
- **天赋**：这一级里目标为 `TALENT` 或 `TALENT_DATA_ONLY`、不属于召唤物、对所有模式和地图有效（`gameTag`、`mapTag` 为 null）的部件，按顺序取其中已解锁的天赋候选（解锁条件同干员-3），分两遍：
  1. **升级**：`prefab` 是干员某个天赋（它的任一候选）的 `prefab` 的候选，升级那个天赋（不看 `index`）：天赋的 blackboard 换成候选的，描述换成升级描述 `upgrade`（为空时保留原来的）；天赋原来不隐藏的仍不隐藏。同一个天赋有几个这样的候选时，最后一个起作用。
  2. **追加**：`prefab` 不是干员任何天赋的、不隐藏、`index` 不小于 0 的候选，追加在第 `index` 个天赋上：描述换成升级描述（为空时保留原来的），候选 blackboard 里天赋没有的键加进来，天赋已有的键保留天赋的值（同名的键是模组给自身的额外加成，如推进之王「自身攻击力和防御力额外+6%」、星熊「自身防御力额外提升4%」，还没有实现）。
  
  之后再按干员-6 取常驻部分。**模组自己的数据**：`index` 小于 0 的候选和隐藏的候选，它们的 blackboard 按顺序合并，交给分支特性（职业-7）读取（如解放者 LIB-X 的 `init_atk`，杰西卡 MAR-Y「范围内存在地面敌人时攻击速度+8」的 `attack_speed`）；它们不改天赋（第一遍匹配上的隐藏候选照样升级它的天赋，如埃癸斯的隐藏天赋）。
- **特性**：这一级里目标为 `TRAIT` 或 `TRAIT_DATA_ONLY`、不属于召唤物、对所有模式和地图有效的部件，按顺序把其中已解锁的特性候选的 blackboard 盖在特性的 blackboard（干员-3）上：同名的键取模组的值，其余保留。追加、替换的特性说明只作展示。
- **范围**：模组自己的天赋里带范围编号、没有 blackboard 的候选给出干员新的攻击范围（职业-19）。
- **还没有实现**：模组特性部件改动的范围（`rangeId`；替身的范围除外，职业-16）、模组自己的数据作为天赋生效（分支特性读取的除外）、召唤物的属性加成、只在某些模式或地图有效的部件。

- 来源：[PRTS「游戏数据基础」oldid=440563](https://prts.wiki/index.php?title=%E6%B8%B8%E6%88%8F%E6%95%B0%E6%8D%AE%E5%9F%BA%E7%A1%80&oldid=440563)「属性」定义：「信赖、潜能和模组提供数值也会在这一步计（算）入，使得原始属性变为原始属性+」；数据：uniequip_table 的 unlockEvolvePhase、unlockLevel，battle_equip_table 的 phases[]；天赋部件替换天赋的方式为推断 INF-0089

### 干员-8 范围表

range_table 的每个范围按编号记录它的格子（`grids` 的 row、col，原样），按编号排序，写进 `packages/content/data/ranges.json`。特性、天赋按编号引用其中的范围（如 职业-11 的近处范围）；格子相对于干员所在格，随干员朝向转动，和攻击范围相同。

- 来源：数据：range_table 的 grids

### 干员-9 队伍天赋

天赋（含模组的升级，干员-7）的**队伍部分**：描述按 干员-6 去掉标签和潜能差值后，第一句以「编入队伍时」（对卡组）或「在场时」（在场上）开头，接着是「所有（友方）【职业或势力】（职业 / 势力的）干员（的）」（职业为先锋、近卫、重装、狙击、术师、医疗、辅助、特种之一，可以不带【】；势力为 干员-10 的势力名称，如【深海猎人】），然后是开头连续的队伍分句，至少一个：

- 属性（和/、属性）（各）带符号的数值，或「提升」加数值（%、秒、/秒）；属性词同 干员-6，另加 初始技力 `sp`；
- 「每秒回复N点生命」：`hp_recovery_per_sec`；
- 效果：「获得N%的物理闪避」（`prob`，物理闪避 `dodgePhys`）、「医疗效果提高N%」（`heal_scale`，治疗倍率 `healingDealtMul`，属性-2）。

第一句也可以以「全场友方单位」「在场时（，）所有友方单位（的）」「在场时（，）全地图的友方单位」开头：在场上、对**所有友方单位**（`all`）。

分句用到的键都要在 blackboard 里，第一句其余部分不能提到「效果」。队伍部分就是 职业、势力或所有友方单位 + 这些键和值，效果的修饰器另记为 `mods`；描述里有「同类效果取最高」时带 `max`。在场上的队伍部分只能有 Buff 能带的属性（`atk`、`def`、`max_hp`、`attack_speed`、`magic_resistance`、`sp_recovery_per_sec`、`hp_recovery_per_sec`），对卡组的不能带效果、不能是所有友方单位，否则不算。

- **对卡组**：组装对局（同步-9）时，一名玩家卡组里每个干员的对卡组的队伍部分，作用于同一卡组里这个职业、或有这个势力的每个干员（包括它自己）：`cost` 加到部署费用（不低于 0），`sp` 加到技能的初始技力，其余的键加到 `talentBb`（部署-4）。
- **在场上**：干员数据的 `fieldTalents`（职业或势力，和 blackboard），干员数据带着自己的势力 `powers`，由模拟按 部署-5 生效。

天赋的其余内容（只对自身的额外加成、按分支或稀有度的加成、触发类效果）还没有实现。

- 来源：数据：character_table 的天赋文字与 blackboard，如安洁莉娜「全场友方单位攻速+8」、白面鸮「在场时所有友方单位的技力自然回复速度+0.3/秒（同类效果取最高）」、临光「在场时，全地图的友方单位医疗效果提高12%」、格拉尼「在场时，所有【先锋】职业干员获得25%的物理闪避」、年「编入队伍时，所有【重装】职业干员的生命上限+20%」、风笛「编入队伍时所有【先锋】干员的初始技力+8」、凛冬「编入队伍时所有【先锋】职业干员的部署费用-1」、艾雅法拉「在场时，所有友方【术师】职业干员的攻击力+16%」、赫默「在场时，所有友方【医疗】职业干员攻速+14」、桃金娘「在场时，所有【先锋】干员每秒回复28点生命」、斯卡蒂「编入队伍时，所有【深海猎人】干员的攻击力+16%」；对卡组的只作用于这名玩家自己的卡组、在场上的作用于所有玩家的干员、属性按 技能-5 换算为推断 INF-0094

### 干员-10 势力

干员的势力 `powers`：主势力（`mainPower`，没有时取干员自身的字段）的国家、组织、队伍 id（`nationId`、`groupId`、`teamId`，为 null 的略去），再依次加上每个副势力（`subPower`）的，去掉重复。主势力的三项 id 另记为 `mainPower`（没有的为 null）。势力的名称按 id 记录在 `packages/content/data/powers.json`（handbook_team_table 的 `powerName`，按 id 排序）。天赋按名称引用势力（干员-9）。

- 来源：数据：character_table 的 mainPower、subPower、nationId、groupId、teamId，handbook_team_table 的 powerId、powerName

### 干员-11 范围天赋

天赋（含模组的升级）的**范围部分**：描述按 干员-6 处理后，第一句以「攻击范围内（的）」加对象开头——敌军或敌人（敌人）、友方单位或友方干员（干员）、远程干员（远程位的干员）——然后是开头连续的范围分句，至少一个：属性（和/、属性）（各）带符号的数值，或「提升」「降低」加数值（%、/秒）。属性词与修饰器（属性-2）：

| 属性词 | 键 | 不带 % | 带 % |
|---|---|---|---|
| 攻击力 | `atk` | `atkFlat` | `atkPct` |
| 防御力 | `def` | `defFlat` | `defPct` |
| 生命上限、最大生命值 | `max_hp` | `hpFlat` | `hpPct` |
| 法术抗性 | `magic_resistance` | `resFlat` | `resPct` |
| 攻击速度、攻速 | `attack_speed` | `aspd` | — |
| 移动速度 | `move_speed` | — | `movePct` |
| 技力自然回复速度 | `sp_recovery_per_sec` | `spRecoveryFlat`（/秒） | — |

修饰器的值取 blackboard 里这个键的值（带 % 的就是比例）；写法是「—」的、键不在 blackboard 里的分句不算。第一句其余部分不能提到「效果」。范围部分就是对象和这些修饰器，作为干员数据的 `rangeTalents`，由模拟按 部署-6 生效。

干员-6、干员-9 的分句也检查 %：`atk`、`def`、`max_hp` 必须带 %（按 技能-5 是直接乘算的比例），其余的键不能带 %，否则不算。

- 来源：数据：character_table 的天赋文字与 blackboard，如伊芙利特「攻击范围内的敌军法术抗性-44%」（`magic_resistance` −0.44）、闪灵「攻击范围内的友方单位防御力+65」（`def` 65）、夜莺「攻击范围内的友方单位法术抗性+17」、莫斯提马「攻击范围内的敌人移动速度-18%」、蜜莓「攻击范围内的远程干员最大生命值+12%」；按有无 % 选修饰器为推断 INF-0095

### 干员-12 几率天赋

天赋（含模组的升级）第一句里有下列分句之一、blackboard 有它要的键时，它是**几率天赋**（「攻击时」可以自成一个分句，和下一个分句连起来读）：

| 分句 | 几率 | 效果 |
|---|---|---|
| 攻击时（，）（有）N%（的）几率/概率（使）（当次攻击的）攻击力提升至M%（或以「每次攻击」「造成伤害时」「造成物理伤害时」开头） | `prob` | 倍率 `atk_scale` |
| 攻击时 / 普通攻击和技能释放时（，）（有）N%（的）几率当次攻击的攻击力+M% | `prob` | 这次攻击的攻击力直接乘算 + `atk` |
| 攻击时有N%（的）几率无视目标的防御 | `prob` | 这次攻击的每一下无视目标全部防御（`ignoreDef` 1） |
| 攻击时有N%（的）几率/概率造成二连击 / 连续攻击两次 | `prob`（没有时 `attack@prob`） | 这次攻击的每个目标受到的次数 × 2 |
| 攻击有N%几率造成相当于攻击力M%的物理伤害 | `prob` | 倍率 `atk_scale` |

第一种紧跟的分句是「并（使敌人）晕眩（敌人）N秒」且 blackboard 有 `stun` 时再带晕眩 `stun` 秒；是「且额外攻击一个目标」时再带一个目标。几率天赋作为干员数据的 `critTalents`，由模拟按 攻击-4 生效。

- 来源：数据：character_table 的天赋文字与 blackboard，如克洛丝「攻击时，20%几率当次攻击的攻击力提升至160%」、古米「攻击时，18%几率当次攻击的攻击力提升至200%，并晕眩敌人1秒」、风笛「每次攻击有25%的概率攻击力提升至130%，且额外攻击一个目标」、陨星「普通攻击和技能释放时，30%几率当次攻击的攻击力+60%」、芙兰卡「攻击时有20%的几率无视目标的防御」、慕斯「攻击时有23%的几率连续攻击两次」、Misery「攻击时有10%概率造成二连击」（`attack@prob`）、艾拉「攻击有30%几率造成相当于攻击力160%的物理伤害」；同一句里更多的条件（如概率在某条件下变化、对某些目标必定触发）还没有实现；攻击力加成按直接乘算、二连击为次数翻倍为推断 INF-0255

### 干员-13 时间天赋

天赋（含模组的升级）第一句以下列之一开头时，它是**时间天赋**：

- 「每在场上停留N秒」（每隔 blackboard `interval` 秒升一级，最后一个分句是「最多（可以）叠加N层/次」，最多 `max_stack_cnt` 级）；
- 「在战场停留N秒后」（`interval` 秒后一次）；
- 「部署后N秒内」（部署后 `duration` 秒）。

其余部分按「，」和「且」分句，每一句都要给出修饰器：范围分句的写法（干员-11，前面可以有「自身」），或「获得抵抗」（`one_minus_status_resistance` 直接加算到一减状态抵抗率，属性-1）。有一句不是这样的，就不是时间天赋。时间天赋作为干员数据的 `timedTalents`，由模拟按 部署-7 生效。

- 来源：数据：character_table 的天赋文字与 blackboard，如塞雷娅「每在场上停留20秒，攻击力+5%，防御力+4%，最多叠加5层」、洛洛「每在场上停留N秒，攻击力+N%，最多可以叠加N次」、Sharp「在战场停留N秒后，自身攻击速度+N」、煌「在战场停留12秒后获得抵抗」、松果「部署后60秒内技力自然回复速度+0.5/秒」；[PRTS「术语释义」oldid=440223](https://prts.wiki/index.php?title=%E6%9C%AF%E8%AF%AD%E9%87%8A%E4%B9%89&oldid=440223) 抵抗

### 干员-14 部署天赋

天赋（含模组的升级）第一句以「部署后立即」或「部署后立刻」开头、紧接的第一个分句是下列之一时，它是**部署天赋**，作为干员数据的 `deployTalents`，由模拟按 部署-8 生效：

| 分句 | 效果 |
|---|---|
| 获得N点技力 | 技力 `sp` |
| 随机获得A~B点技力 | 技力在 `sp_min` 到 `sp_max`（不含）之间 |
| 恢复全场友方单位N点生命 | 治疗每名干员 `value` |
| 恢复全体友方单位的生命值（恢复量为攻击力的N%） | 治疗每名干员 `heal_scale` × 攻击力 |

- 来源：数据：character_table 的天赋文字与 blackboard，如炎熔「部署后立即获得35点技力」、艾雅法拉「部署后立即随机获得7~15点技力」（`sp_min` 7、`sp_max` 16）、Lancet-2「部署后立即恢复全场友方单位500点生命」、末药「部署后立刻恢复全体友方单位的生命值，恢复量为末药攻击力的160%」、年「部署后立即获得3层护盾」；[PRTS「术语释义」oldid=440223](https://prts.wiki/index.php?title=%E6%9C%AF%E8%AF%AD%E9%87%8A%E4%B9%89&oldid=440223) 护盾「每层护盾可以抵挡一次伤害」

### 干员-15 替身天赋

傀儡师（职业-15）的天赋描述保留「<替身>」，去掉其余富文本标签和全角括号里的潜能差值后：

- 以「<替身>使周围敌人移动速度-N%且每秒造成相当于M%攻击力的法术伤害」开头、blackboard 有 `move_speed` 和 `atk_scale` 时，是替身的**光环**：`moveMul` = 1 + `move_speed`，`scale` = `atk_scale`；替身不攻击。
- 描述里有「<替身>不攻击」时，替身**不攻击**。
- 以「<替身>攻击造成法术伤害」开头时，替身的攻击造成**法术伤害**（`arts`）；描述里还有「受到的物理与法术伤害减少N%」、blackboard 有 `damage_resistance` 时，替身受到的物理、法术伤害 × (1 − `damage_resistance`)（`taken`）。
- 隐藏候选没有替身天赋。

读替身天赋（和替身的范围，职业-16）时，模组同一级里对同一个天赋的几个候选（干员-7）按顺序合并：后面的候选有升级描述、范围编号时取它的，blackboard 盖在前面的上。这样，归溟幽灵鲨的模组 PUM-X 2、3 级里，只改数据的部件给出光环的新数值和范围，另一个部件给出描述和「替换时」的技力。替身天赋作为 `doll` 的 `attack`、`aura`、`arts`、`taken`，由模拟按 职业-16 生效。

- 来源：数据：character_table 的天赋文字与 blackboard，如归溟幽灵鲨「<替身>使周围敌人移动速度-20%且每秒造成相当于20%攻击力的法术伤害」（`move_speed` −0.2、`atk_scale` 0.2）、若叶睦「<替身>不攻击」、贝娜「<替身>攻击造成法术伤害且受到的物理与法术伤害减少43%」（`damage_resistance` 0.43，精英 0 的描述没有减伤）；battle_equip_table 中归溟幽灵鲨模组 2、3 级的 `TALENT_DATA_ONLY` 与 `TALENT` 部件；[PRTS「归溟幽灵鲨」oldid=361755](https://prts.wiki/index.php?title=%E5%BD%92%E6%BA%9F%E5%B9%BD%E7%81%B5%E9%B2%A8&oldid=361755)「※<替身>不进行普通攻击」、移动速度为最终乘算；模组候选的合并为推断 INF-0199，光环天赋即替身不攻击为推断 INF-0200

### 干员-17 条件增益

天赋（含模组的升级）第一句（以「，」分句）里从第一个**以条件开头**的分句起，是它的**条件部分**（之前的分句归常驻部分，干员-6）：以条件开头的分句开始一项，它后面的内容和其后直到下一个条件的分句，都是关于干员自身的分句（属性或 干员-16 的效果），合成这一项的修饰器（属性键按 技能-5 换算）。条件（职业-18、职业-24）：

| 开头 | 条件 |
|---|---|
| 未阻挡敌人时 | `notBlocking` |
| 阻挡敌人时 | `blocking` |
| 阻挡两个/三个（及）以上的敌人时 | `blockingAtLeast`，数取 `cnt`（没有时取描述的数） |
| 攻击范围内存在N名及以上（的）敌人时；攻击范围内存在/有敌人时 | `enemies`，`cnt`（没有时 N；后者 1） |
| 攻击范围内至少有N名其他（友方）干员时 | `allies`，`cnt`（没有时 N） |
| 攻击范围内存在生命值低于一半的敌人时 | `lowHpEnemies`，`hp_ratio`（没有时 0.5） |
| 攻击范围内存在处于X损伤爆发期间的敌方单位时（X 为神经、侵蚀、灼燃、凋亡、狂躁） | `burstEnemies`，只看这种元素 |
| （当）周围四格（内）没有敌人时 | `noEnemies4` |
| 周围四格内仅存在一名敌人时 | `soleEnemy4` |
| （当）周围四格（内）没有其他友方单位时 | `aloneUnits4` |
| 周围8格（内）没有友方干员时 | `alone8` |
| 技能未开启时 | `notInSkill` |
| 生命值高于/低于N%时 | `hpAbove` / `hpBelow`，`hp_ratio` |

条件后的分句以「改为」开头时（「每秒回复2%生命值，周围8格没有友方干员时，改为每秒回复4%生命值」），这一项给的是比常驻部分多出的部分：同一个分句，各键的值换成 blackboard 里以「.<键>」结尾的键的值（绮良 `kirara_t_2.…`），减去（乘的修饰器为除以）用原键的值时的修饰器；没有这两个值时不算。

从第一个条件起每个分句都要这样读得出来、每一项至少有一个修饰器、后面的句子不能提到「效果」，否则整个天赋没有条件部分。条件部分作为干员数据的 `talentTrait.whiles`，由模拟按 职业-24 生效。

### 干员-18 按目标的倍率

天赋（含模组的升级）第一句是「攻击 / 对 + 目标 + （的）敌人 / 目标 / 单位（时）（，）」（或「攻击【标签】时（，）」）再加它得到的、整句只有这些、后面的句子不提「效果」时，它是**目标部分**：

| 目标 | 条件（职业-17、职业-24） |
|---|---|
| 被阻挡 | `blocked` |
| 未被阻挡 | `unblocked` |
| 未被自身阻挡 | `notOwnBlocked` |
| 使用远程武器 | `rangedFoe` |
| 空中、飞行 | `flying` |
| 生命值低于 / 高于N% | `hpBelow` / `hpAbove`，`hp_ratio` |
| 重量小于等于 / 大于等于N | `light` / `heavy`，`value`（没有时 N） |
| 【萨卡兹】【无人机】【感染生物】 | `tag`：`sarkaz`、`drone`、`infection`（敌人的标签，关卡-1） |
| 被战栗 | `status`：`disarmedCombat`（状态-5） |

| 得到 | 效果 |
|---|---|
| 攻击力提升至M%；攻击力+M% | 攻击倍率 `atk` = `atk_scale` |
| （自身）（造成（的））伤害提升 / 提高 / +M% | blackboard 有 `atk_scale` 时攻击倍率 `atk` = 它，否则伤害倍率 `dmg` = `damage_scale` |
| 无视目标/其N（点）（的）防御力 | 无视防御 `defFlat` = `def_penetrate_fixed` |
| 无视目标/其N%的防御力 | 物理穿透 `defPct` = `def_penetrate` |

缺对应的键时不算。目标部分作为干员数据的 `talentTrait.vs`，由模拟按 职业-24 生效。优先攻击某些目标（「优先攻击【无人机】单位，且……」）和同一句里更多的效果还没有实现。

- 来源：数据：character_table 的天赋文字与 blackboard，如守林人「攻击使用远程武器的敌人时，攻击力提升至145%」、和弦「攻击被阻挡的敌人造成伤害提升20%」（`atk_scale` 1.2）、惊蛰「攻击未被阻挡的敌人时攻击力提升至123%」、熔泉「攻击【萨卡兹】敌人时，攻击力提升至150%」、孑「攻击【感染生物】时，攻击力提升至150%」、流星「攻击空中目标时，攻击力提升至140%」、巡林者「攻击飞行目标时，攻击力+50%」（`atk_scale` 1.5）、苦艾「攻击生命值低于40%的敌人伤害提高30%」、戴菲恩「攻击生命值高于80%的敌人时造成的伤害提高20%」、裁度「攻击未被自身阻挡的敌人时，自身造成的伤害+25%」、燧石「对未被自身阻挡的敌人造成的伤害提升45%」、歌蕾蒂娅「攻击重量小于等于3的敌人时攻击力提升至136%」、见行者「攻击重量大于等于3的敌人时无视目标200的防御力」、锏「攻击被战栗的目标时，无视目标30%的防御力」；level 数据的 enemyTags；按键选攻击倍率或伤害倍率、目标条件的判定为推断 INF-0253

### 干员-19 命中效果

天赋（含模组的升级）第一句是下列之一、blackboard 有它要的键、后面的句子不提「效果」时，它是**命中部分**，作为干员数据的 `talentTrait.onHit`，由模拟按 职业-24 生效：

| 句子 | 效果 |
|---|---|
| 攻击时（有）N%（的）几率/概率使目标束缚 / 晕眩 / 停顿 / 寒冷 / 沉睡M秒 | 几率 `prob`（没有时 `attack@prob`），状态（状态-5）`root`、`stun`、`sluggish`、`cold`、`sleep`，秒数取 `duration` 或 `frozen_duration`、`stun`、`sluggish`（或 `attack@sluggish`）、`cold`、`sleep` |
| 攻击时有N%的几率对攻击目标造成M秒的停顿 | 几率，停顿 |
| 攻击时对攻击目标造成M秒的停顿；攻击造成M秒寒冷 | 停顿、寒冷 |
| 攻击使目标的特殊能力失效，持续M秒 | 沉默 `silence`，`silence` 或 `duration` 秒 |
| 对每个敌人首次造成伤害时/后，使其/目标（的）战栗 / 特殊能力失效（，持续）M秒 | 只对每个敌人的第一下（`first`）：战栗 `disarmedCombat`（`not_combat` 或 `duration` 秒）、沉默 |
| 攻击敌人时对目标施加N%的【法术脆弱】，持续M秒 | 状态法术脆弱 `artsFragile`，强度 `damage_scale` − 1，`weak[magic][limit]` 或 `duration` 秒 |
| 攻击（时有N%的几率）使目标法术抗性-N%，持续M秒 | （几率）`duration` 秒的修饰器：法术抗性直接乘算 + `magic_resistance` |
| 造成伤害时有N%概率对敌人施加灼痕效果：攻击力-A%、B%的【法术脆弱】，不可叠加持续M秒 | 几率 `prob`，`duration` 秒的修饰器：攻击力直接乘算 + `atk`，受到法术伤害倍率 × `damage_scale` |
