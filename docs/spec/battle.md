# 战斗循环与同步

### 帧-1 一帧内的顺序

每一帧按固定顺序执行：

1. 这一帧的指令，按服务器封口时的顺序；
2. 费用增长；
3. 出怪；
4. Buff：每个单位按创建顺序，它的 Buff 按获取顺序推进时间、触发、到期（状态-3、状态-4）；
5. 敌人的回合，按创建顺序：解除或检查阻挡（阻挡-1、阻挡-3），攻击（敌人攻击-1），没被阻挡、没有攻击的移动，到达目标点（目标-1），移动后再检查阻挡；
6. 干员的回合，按创建顺序：先放开阻挡数装不下的敌人（阻挡-3），再攻击（攻击-1）；
7. 移除生命归零的单位：阵亡的干员解除阻挡，可以再部署。

第 F 帧的指令在执行第 F 帧时生效，执行完帧号加一。

- 来源：推断 INF-0010

### 随机-1 随机数

对局的随机数用 mulberry32，32 位状态存在世界状态里，随快照保存。初始状态取种子的低 32 位。只用 `Math.imul`、移位和异或，所有引擎结果相同。

- 来源：设计决定，见 [ADR 0011](../adr/0011-numerics-integer-frames.md)

### 同步-1 状态哈希

状态哈希是 32 位 FNV-1a，处理一串数字，每个数字取 IEEE-754 小端字节。这串数字由下面这个对象逐项展开得到：帧号、随机状态、下一个单位编号、下一个出怪序号、全部玩家、全部单位（含基础属性和 Buff）。

展开规则：每个值先记一个类型标记，再记内容。

- 数：−0 记作 0，因为快照（JSON）不能表示 −0；所有 NaN 按同一个值处理。
- 字符串：长度和 UTF-16 码元。
- 布尔值：0 或 1。
- null：只有标记。
- 数组：长度，然后各项。
- 对象：键的个数，然后按键的顺序记每个键（字符串）和值。值为 undefined 的键跳过，因为快照会丢掉它们。

- 来源：设计决定，见 [ADR 0031](../adr/0031-desync-recovery.md)

### 同步-2 快照

快照是世界状态的完整深拷贝，装在第 1 版快照外壳里（ADR 0053），不含当帧的表现事件。从任意一帧的快照恢复后继续执行，每一帧的状态哈希都与不中断执行时相同。外壳格式不对，或数据的帧号与外壳不一致时，拒绝恢复。

- 来源：设计决定，见 [ADR 0053](../adr/0053-interface-schemas.md)
