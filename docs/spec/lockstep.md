# 帧同步

### 同步-3 输入延迟与封口

- **封口**：服务器从第一个座位连上时开始计时，每过 1/30 秒封口一帧。第 F 帧在开始计时 (F + 1) / 30 秒后封口。封口后，这一帧的全部指令随"封口帧"消息发给所有连着的座位，服务器自己的模拟（仲裁）也执行这一帧。
- **指令的帧号**：客户端把指令定在"下一个要执行的帧 + 9"。9 帧就是 0.3 秒。
  - 服务器收到时，那一帧还没封口就照收；已封口就改到下一个没封口的帧，并发"顺延"消息告诉发送者。
  - 同一帧里的指令按到达服务器的顺序执行。
  - 比最后封口的帧超前 90 帧以上的指令一律拒绝，回复错误消息。

- 来源：数据：activity_table.activity.MULTIPLAY_V3.act1multi.constData.maxOperatorDelay（0.3）；把它理解为输入延迟是推断 INF-0011

### 同步-4 追赶

客户端只执行已经封口的帧。

- 每过 1/30 秒，客户端执行的帧数由待执行的已封口帧数（积压）决定：
  - 积压为 0 时不执行；
  - 积压不超过 2 帧（抖动缓冲）时执行 1 帧；
  - 积压更多时执行 `积压 − 1` 帧，最多 5 帧。
- 所以落后的客户端最快以 5 倍速追上。

- 来源：数据：activity_table.activity.MULTIPLAY_V3.act1multi.constData.maxPlaySpeed（5）；把它理解为追赶速度是推断 INF-0012

### 同步-5 哈希校验、断同步恢复、重连

- **哈希校验**：客户端每执行完 30 帧，把状态哈希（同步-1）发给服务器。服务器拿它和仲裁在同一帧的哈希比较。
- **断同步恢复**：不一致时，服务器把仲裁当前的快照（同步-2）发给这个客户端，客户端从快照继续执行。服务器同时记录这次不一致：座位、帧号、双方的哈希。
- **重连**：一个座位连上或重连时，服务器先发仲裁当前的快照，再发此后的每个封口帧。
- **掉线期间**：断线座位的干员留在场上继续战斗，因为模拟不区分座位是否在线。

- 来源：设计决定，见 [ADR 0031](../adr/0031-desync-recovery.md)；断线干员继续作战见 [PRTS「促融共竞」oldid=377839](https://prts.wiki/index.php?title=%E4%BF%83%E8%9E%8D%E5%85%B1%E7%AB%9E&oldid=377839)

### 同步-6 双方都掉线时暂停

所有座位都断开时，服务器停止封口。有座位重新连上后，从停下的帧继续；断开的这段时间不计入帧时间。

- 来源：[PRTS「促融共竞」oldid=377839](https://prts.wiki/index.php?title=%E4%BF%83%E8%9E%8D%E5%85%B1%E7%AB%9E&oldid=377839)：双方玩家均断线时，系统自动暂停作战
